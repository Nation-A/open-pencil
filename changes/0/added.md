- A host that draws the window's top row can hide the sidebar header (logo, name, settings, panel toggle) and drive settings and the panel toggle through `window.openPencil.setEmbeddedChrome` and `chromeCommand`.
- A host can own comment storage through `window.openPencil.setCommentsHost` (threads in, ops out, no plugin-data writes), with @mentions of members it lists, emoji reactions, commenter-only tools for a read-only document, and `focusComment(id)` to open a thread.
- Host-owned comments gain editing in place (Edit in the card's menu, own messages only), a `move` op for dragging one's own pin (`{ type: 'move'; opId; threadId; anchor }`, optimistic, put back when refused), picture avatars from `authorAvatarUrl` / `members[].avatarUrl` with an initials fallback, list filters (unresolved, resolved, mentions of me) and page-order sorting, and a read-only host (`readOnly`) now also blocks edit shortcuts, nudging, paste, cut and drops.
- A read-only document (host `readOnly`, set through `setCommentsHost`) is now fully locked: `store.state.readOnly` is the one signal, the editor ignores every document-changing action and its history, and the layers, properties, pages, menus, context menu and AI tab show editing as disabled or hidden, while inspecting, exporting (a default PNG when no setting is stored), copying and commenting still work. Each reply has its own hover menu (Edit, Delete) for its author in place of the pencil button.
- A read-only document can open the Variables section and dialog to read collections, tokens, values and the inspector, as in Figma; creating, importing, renaming, editing values and deleting stay locked (the editor guard is unchanged).
